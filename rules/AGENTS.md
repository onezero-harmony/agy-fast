# agy-fast Tool Routing & Latency Hygiene Rules

Use `agy-fast_fast` MCP tools where batching amortizes the fixed per-call remote check (~1.8s) and keeps context lean, and use built-in `read_file` for allowlisted fast reads (~7ms, 46 KB inline cap per call):

| Task | Preferred Tool | Reason |
| :--- | :--- | :--- |
| Outline unknown large files (>300 lines; prefer 10-20 files/batch, max 40: TS/JS/Vue/Svelte/CSS/Py/GDScript/Go/Rust/Java/MD/JSON/YAML) | `read_slices({ outlines: [...] })` | 1 call maps exact symbol/section line ranges without blind full-file dumps |
| Read small files (<300 lines) OR **any** known line ranges after outlining (even 4-8 scattered ranges) | Built-in `read_file` (parallel in one turn, with `StartLine`/`EndLine` <=200 lines) | Locally allowlisted (~7ms, **0 remote check**) + **46 KB/call** inline vs MCP's 8.8 KB total cap |
| Run >=2 text/regex/glob/fuzzy/read-only `git` queries (even across multiple directories/repos) | `batch_search` (pack ALL queries into **one** call via per-query `path`) | 1 remote check + concurrent local execution (<70ms), hard-capped <=8.8 KB inline |
| Edit >=2 blocks in one file, edit/create/overwrite >=2 files in one turn, OR any edit + verify | `apply_edits` (`bestEffort: true` for >=3 files; optional `verify`) | Replaces N serial checks + verify turn; `bestEffort` commits valid files & returns closest-line / drifted-line hints |
| Run >=2 independent non-interactive shell commands in one turn | `run_checks` (`outputMode: "compact"` for build/lint/test; `"full"` for diagnostic/inspection scripts) | 1 remote check + concurrent execution instead of N serial `run_command` checks |

## Rules

1. **Direct invocation (no schema read turn)**: When `agy-fast_fast` tools are lazily loaded, call `call_mcp_tool` directly with `ServerName: "agy-fast_fast"` using the schemas below. Do **not** spend a turn reading `mcp/agy-fast_fast/*.json` first.
2. **Outline via `read_slices`, read code via parallel `read_file`**: On unknown files >300 lines, call `read_slices({ outlines: [...] })` first (you may piggyback 1-2 tiny <=120-line slices in the same call), then fetch needed <=200-line sections with parallel built-in `read_file(StartLine, EndLine)`. **Do NOT** use `read_slices({ slices })` to bulk-read >150 lines across multiple files (MCP output is hard-capped <=8.8 KB inline and will truncate), and **do NOT** blind-read `1-800` on large unknown files.
3. **Keep images out of long coding sessions (TTFT & cache hygiene)**: Loading `.png`/`.jpg`/`.webp` images (UI screenshots, business/voucher/receipt images, or debug captures) into a long (>150k-token) coding conversation can trigger full prompt-cache invalidation and a **3-7x TTFT cliff (40-97s/turn)**. Delegate visual inspection of any image to a subagent that returns a **text-only** list of findings (values, file paths, selectors, concrete fixes); do **not** read those images in the main coding session unless strictly unavoidable.
4. **Prevent context bloat & cache expiry**: Keep subagent reports structured and concise (no raw file dumps). For large `git diff`/`git show` in `batch_search`, run `--stat` or path-scoped diffs first. In long (>200k-token) multi-phase tasks, batch tool calls aggressively—avoid tiny single-read/single-search turns that pay full TTFT for <300 output tokens—and recommend `/compact` or a fresh session between major phases (e.g., audit -> backend -> frontend).
5. **Apply across all directories, use `bestEffort: true` for >=3 files & circuit-break corrupted MCP args**: Use `apply_edits` and `batch_search` consistently for code, Vue/HTML/CSS, docs, scripts, and scratch folders. For `apply_edits` touching >=3 files, pass `bestEffort: true` (batches <=6-8 files) so one mismatch never rolls back valid files. If `apply_edits` reports nested-argument serialization corruption (e.g., `boolean`/`null` in `edits`), **do NOT retry the same payload**—immediately fall back to parallel built-in `edit_file` / `write_file`.
6. **Pack into ONE MCP call per turn, use the startup snapshot & brief swarm workers**: Combine cross-repo searches into one `batch_search`, combine edits + verify into one `apply_edits`, pass `cwd`, read the `SessionStart` snapshot before running `ls`/`git status`, and avoid issuing 2 parallel `call_mcp_tool` calls of the same kind in one turn. When spawning swarm workers for codebase tasks, note in their brief to batch read-only exploration into one compound command and use parallel ranged `read_file` (<=200 lines) instead of serial `ls`/`grep` calls (swarm workers do not receive `SessionStart` snapshots and may not have `agy-fast` MCP mounted).

## Quick Schemas (`ServerName: "agy-fast_fast"`)

- **`batch_search`**: `{ cwd?, queries: [{ type: "text"|"regex"|"glob"|"fuzzy"|"git", pattern, path?, glob?, fileType?, multiline?, outputMode?: "content"|"files_with_matches"|"count", sortBy?: "path"|"mtime", caseSensitive?, contextLines?: 0..5, maxResults?: 1..200 }], maxChars?: 500..8800 }` (1-20 queries; glob uses `*`/`{a,b}`, not regex `|`; `path` relative or absolute; read-only git only).
- **`apply_edits`**: `{ cwd?, edits: [{ path, hunks?: [{ target, replacement, startLine?, endLine?, replaceAll? }], create?: string, overwrite?: boolean, delete?: boolean, moveTo?: string, pruneEmptyDirs?: boolean }], dryRun?, bestEffort?, pruneEmptyDirs?, verify?: string, verifyTimeoutSec?, maxVerifyChars?: 300..7500 }` (1-50 files; `delete` is exclusive; `moveTo` may combine with `hunks`; `delete`/`moveTo`/`pruneEmptyDirs` stay strictly inside `cwd`).
- **`read_slices`**: `{ cwd?, outlines?: string[], slices?: [{ path, ranges: [[startLine, endLine], ...] }], maxChars?: 1000..8800 }` (prefer 10-20 outlines/batch, max 40; 1-based inclusive line ranges).
- **`run_checks`**: `{ cwd?, commands: [{ name?, command, cwd?, timeoutSec? }], concurrency?: 1..8, timeoutSec?, outputMode?: "compact"|"full", maxChars?: 500..8800 }` (1-12 commands).
